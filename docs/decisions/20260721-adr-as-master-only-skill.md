# Decision: ADR の起票・維持を master-only スキルに切り出す

Date: 20260721
Status: Accepted

## Context

`knowledge-capture` は配布可スキルであり、その決定木は「一回限りの設計・アーキテクチャ判断」を
`docs/decisions/[YYYYMMDD]-[slug].md` に Nygard 形式で書き込む枝を持っていた。しかし ADR の
権威は文書そのものではなく**批准プロセス**から来る。批准の仕組みを持たない配置先で単独生成された
ADR ファイルは、その組織の公式な決定記録と競合する「影の決定ログ」になり、誰もレビューしない
個人メモが決定記録のコスプレをする。

同時に、このリポジトリの ADR 群は 7 本・週 1 ペースで増えており、
[20260715-docs-lifecycle-tiers](20260715-docs-lifecycle-tiers.md) で rule-audit の剪定対象外と
決めた以上、単調増加する前提にある。Superseded / Amended の印付けと近縁 ADR の検出という
判例集の維持運用が必要だが、これは「知見をドキュメントに振り分ける」という knowledge-capture の
責務とは別物で、本文 245 行中 40 行強を占めながら片手間で持つには重い。

## Decision

ADR の起票・維持を master-only スキル `adr` として独立させ、配布可スキル `knowledge-capture`
からは ADR の語彙・形式・書き込みを完全に削除する。起票条件は「却下した代替案があるか」の一点とする。

## Rationale

- **判断は普遍、形式は組織固有**。「代替案を却下した決定は記録に値する」という判断は配置先でも
  真なので knowledge-capture は検知能力を保持する。変わるのは出口だけで、決定・理由・却下案を
  `.steering/[task]/decisions.md` に記録し「チームの決定記録に上げるか検討してください」と
  添えて終わる。**定型フォーマットを生成しない** — 独自の様式を持つ組織に Nygard 形式を
  差し出すのは形式の押し付けであり、「単独生成された ADR 形の成果物」をファイルではなく
  テキストで再生産することになる
- **配布可スキルに master-only スキル名を書かない**ことで、境界の相互明記が不要になる。
  配置先には存在しないスキルを指す死んだ参照を作らずに済み、同じ入力を読むスキルが増えることに
  よる片側修正のリスクも増えない
- 起票条件を「却下した代替案があるか」に限ると、Alternatives considered が埋まらない =
  ADR にしない、で自己判定できる。既存 7 本の実態も「見送り・却下の記録」である

## Consequences

- Good: 配置先で影の決定ログが生まれない。ADR の形式・ライフサイクルを知るのは `adr` だけになり、
  knowledge-capture が小さくなる
- Good: `scripts/deploy_skills.py` の `MASTER_ONLY` に登録したため、配置は機械的に拒否される
- Bad: `adr` は人手トリガーのみで自動起票の経路がない。呼ばれない状態が続くと
  「起票実績ゼロ = 不要」と判断されうるが、それは設計の帰結であって需要の不在ではなく、区別できない
- Bad: 起票条件が緩い可能性がある。design-doc は Alternatives considered を標準セクションに
  持つため、design-doc を通ったタスクはほぼ全て条件を満たす。人手トリガーが実質のゲートになる
  前提の設計であり、この前提が崩れると ADR が増えすぎる

## Alternatives considered

| Alternative | Reason rejected |
|-------------|-----------------|
| 出力先をカートリッジ化する（配置先の既存 ADR 方式を検出して切り替える） | 問題は置き場所ではなく権限。批准プロセスを持たないチームでは、どこに置いても単独生成された ADR はコスプレになる |
| knowledge-capture に ADR 枝を残し「配布版はドラフトのみ」の 1 分岐にする | master 側の Superseded / 近縁検出という成長余地を吸収できず、分岐は孤立 subagent の誤読余地を残す |
| 配布版が Nygard 全節（または簡易 4 項目）のドラフトを提示する | 配布版に ADR 形式の定義が残り、master-only になるのが「ファイル書き込み」だけになる（分割が半分で終わる） |
| `adr` も配布可にする | ADR は一人で決める成果物ではない。批准の仕組みを持たない配置先で単独生成すると無用なドキュメントが増える |
| 配布可スキルに ADR の帰属先として `adr` を書く | 配置先には存在しないスキル名を指す死んだ参照になる（design-premortem が検出） |
| ADR 起票条件を現行維持（「一回限りの設計・アーキテクチャ判断」） | 発火条件が主観的。同じ「条件不明で発火しない」問題で glossary は空のまま 5 週間放置された |
| ADR の置き場を `docs/adr/` に改名する | `docs/decisions/` は MADR のデフォルトで既に標準的。改名すると CLAUDE.md・README・rule-audit・既存 7 本の相互リンクが追随対象になり、片側修正のリスクだけ増えて機能的な利得がない |
