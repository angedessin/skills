## design-premortem の費用対効果（20260721・N=1）

`20260721-adr-skill-extraction` の design.md に実行した実測値。

**コスト**: subagent 1 回

**所見の内訳**: 設計本文を修正 11 件 / 人間の判断に委ねる 4 件 / 反論して不採用 1 件 /
攻撃の前提そのものが誤り 1 件

**最大の価値は「設計者が書いた瞬間には見えない矛盾」の検出だった。**
Constraints に「配布可スキルから master-only スキルを参照しない」と書きながら、
Key components には配布可スキル 3 本に master-only スキル名を書く計画が並んでいた。
実装していれば配置先で死んだ参照になり、気づくのは配置先で誤読が起きたとき。

なぜ設計者（自分）に見えなかったかというと、**Key components 表に「変更後の記述」が無く、
原本を開かないと制約違反を判定できない粒度だった**から。表に判定可能な情報を持たせれば
書いた瞬間に気づけたはずで、これは design-doc 側の構造の問題として修正した（v1.7）。

**渡す情報の切り分けが効く**: 遮断すべきはセッションの文脈であって、リポジトリの事実ではない。
今回は「design.md のみを渡す」を誤って「リポジトリ探索も禁止」と解釈した結果、前提が誤った
所見が 2 件混ざった（実在する `--purity` オプションを「未確認」と指摘 / 既に廃止された
還流経路を前提にした指摘）。会話履歴のみを遮断すればバイアス排除の効果は保たれ、この偽陽性は
避けられる（design-premortem v1.1 で明文化）。なお N=1 のため発生「率」は語れない。
言えるのは機構（裏取りできなければ誤った前提を書きうる）まで。

**設計の論理矛盾・スコープ・受け入れ条件の検証可能性についての所見は、リポジトリを見なくても
精度が高い**。前提の事実確認を要する所見だけが裏取りを必要とする。
