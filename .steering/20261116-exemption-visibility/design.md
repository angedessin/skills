# テストの免除を、レビューと PR で見えるようにする

Status: APPROVED

出どころ: スキル評価レポート（`.tmp/skill-eval-report-20261115.md`。追跡外）の M1。もとは H1 と 1 つの設計だったが、プレモータムの論点 B で分けた（20261116・ユーザー）。H1 は `.steering/20261116-verify-tree-guard/`。プレモータムの所見の全文もそちらにある。

## 目的

実装中に足したテストの免除（`test-exemptions.md`）を、コードレビューと PR で人が必ず目にするようにする。今は Claude が承認なしで足せて、レビューの担当も PR の本文も拾わない。

## 決定済み（20261116・ユーザー。すべて推奨案）

- 免除を足すのは承認なしのまま。見えるようにするだけ
  - 却下: 承認制にする — ゲートに差し戻されるたびに止まり、ゲートを外したくなる
  - 却下: 「テストを弱める」だけ承認制 — 節ごとに扱いが分かれ、hook と手順が複雑になる
- レビューの担当に免除の妥当性は見させない。載せるだけで、判断は人がする
- 足して後で消した免除（テストを書いて解消した）は PR に載せない。タスクを閉じて消えた免除は載せる
- `.steering/` を gitignore している配置先は対象外。免除ファイルが無視されているときは「確かめられない」と出す
- 課金のある回帰は、新規 2 ケースと、本文を変えたスキルの停止のケースに絞る

## 推奨から変えた点（確認してほしい）

もとの論点 3 の推奨は「pr-create はスクリプトを持たず、本文に git のコマンドを書く」だった。これをやめ、**同じスクリプトを 2 つのスキルに置く**形にする。

- 理由 1: 「解消した免除は載せず、閉じたタスクの免除は載せる」を決めたので、コマンド 1 本では書けなくなった
- 理由 2: プレモータムの所見 7（引用符の無いパスで閉じたタスクの分が消える・レビューの側と数が合わない）は、機械でテストできる形でないと防げない
- 代わりに増えるもの: pr-create に `scripts/` ができ、配るファイルが 1 つ増える。2 つの写しがずれないよう、`test:skills` で一致を検査する

## 対象 / 対象外

対象:

- 免除を数えるスクリプト（frontend-code-review と pr-create に同じものを置く）
- frontend-code-review の報告と、pr-create の本文に免除を載せる
- それを見る評価のケース 2 件

対象外:

- 免除の理由が妥当かの判定
- `.steering/` を gitignore している配置先（「確かめられない」と出すところまで）
- ゲート（`stop-test-gate.sh`）の変更。行の判定の規則を読むだけで、書き換えない
- `count-diff.sh` の変更（もとの案では出力を足す予定だったが、別のスクリプトに分けたので触らない。既存のテストも変えない）

## 振る舞い

### スクリプト `list-exemptions.sh`

```
list-exemptions.sh [--base <ref> [--worktree]]
  指定なし            HEAD と作業ツリーを比べる（未追跡の免除ファイルも見る）
  --base <ref>        <ref> との分岐点と HEAD を比べる
  --worktree          --base と一緒に。分岐点と作業ツリーを比べる
  GIT=<path>          使う git
```

- **載せる行:** 「前」（HEAD か分岐点）の版に無く、「今」の版にある免除の行。行の判定はゲートと同じ規則にする。比べるのは節・パス（`` ` `` と `./` を外した形）・理由の組
  - 理由だけ変わった行は、新しい行として載る（新しい理由を人が見る）
  - 行が消えただけなら載らない
- **閉じたタスクの免除（`--base` のときだけ）:** 分岐点から HEAD までのコミットで足され、HEAD では免除ファイルごと無くなっているもの。ファイルが消える直前の版と、分岐点の版を比べる。「閉じたタスク」と印を付けて載せる
  - ファイルは HEAD に残っていて行だけ消えた場合は、解消したものとして載せない
- **出力:**
  ```
  exemptions: 2
    [テスト不要] src/a.ts — 文言だけの変更（20261116） (.steering/20261116-x/test-exemptions.md)
    [テストを弱める] src/b.test.ts — 仕様の変更で不要になった (閉じたタスク: .steering/20261101-y/test-exemptions.md)
  ```
  0 件は `exemptions: 0` だけ
- **分からないとき:** `exemptions: unknown (<理由>)` を出し、終了コードは 0。免除ファイルが gitignore で無視されている・git の呼び出しが途中で失敗した、など。免除が読めないことでレビューや PR を止めない
- **終了コード:** 0 = 数えた、または分からないと出した／2 = 引数の誤り・git が動かない・リポジトリの外（`count-diff.sh` と同じ）
- パスでの絞り込み（`-- <パス>`）は受けない。免除ファイルは常に全部見る（絞ると必ず消えるため）
- 読むだけで、何も書かない

### frontend-code-review

- Step 1 で、`count-diff.sh` と同じ範囲の指定（`-- <パス>` を除く）で `list-exemptions.sh` を呼ぶ。大きい差分で止まるときは、数えた値と一緒に免除の件数も示す
- Step 4 の報告に「この差分で足したテストの免除」の節を必ず書く。スクリプトの出力をそのまま載せる
  - 0 件: 「なし」
  - `unknown`: 「確かめられない」と理由
  - スクリプトが 2 で終わった・スクリプトが無い: 「レビューできなかったもの」に書いて続ける（レビューは止めない）
- 版を 2.2 にする

### pr-create

- Step 3 で `list-exemptions.sh --base <ベース>` を呼び、1 件以上なら本文に「テストの免除」の節を書く。0 件なら節を書かない。`unknown` なら「確かめられない」と理由を書く
- Step 4 で示す内容に、免除の件数を 1 行で添える（本文を読み飛ばしても目に入るように）
- スクリプトが 2 で終わった・無いときは、そう伝えて続ける（PR の提示は止めない）
- 版を 2.1 にする

## テスト方針

- スクリプトは `tests/skills/run_count_diff.py` と同じ型で、一時リポジトリを作って流す。既存のテストは変えない
- 2 つの写しの一致は、テストの 1 項目として検査する（片方だけ直すとすぐ落ちる）
- SKILL.md の本文の変更は、評価のケースで確かめる
- このリポジトリには vitest が無く、Stop のテストのゲートは動かない。`test-exemptions.md` は作らない

## 悲観的に見ると

- 免除を載せても、人が読み飛ばせば同じ。承認制を選ばなかった以上、これは受け入れる
- 同じスクリプトが 2 か所にある。テストで一致を見るが、配置先（マスターと同期しない）では片方だけ直されうる
- 「閉じたタスクの免除」の判定は、免除ファイルを消したコミットを `git log` で探す。squash merge の後のブランチなど、履歴の形によっては拾えない場合がありうる。テストで確かめるのは、このリポジトリの運用（merge コミットで統合）の形だけ
- 評価の 2 ケースは各 3 回。10 回に 1 回の載せ忘れを見つける確率は 27%
