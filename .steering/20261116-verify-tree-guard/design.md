# 検証役の作業ツリーの見張り

Status: DRAFT

出どころ: スキル評価レポート（`.tmp/skill-eval-report-20261115.md`。追跡外）の H1。もとは M1（テストの免除の見える化）と 1 つの設計だったが、プレモータムの論点 B で分けた（20261116・ユーザー）。M1 は `.steering/20261116-exemption-visibility/` で先に進める。**このタスクは、M1 が main に入ってから着手する。**

末尾の「プレモータム所見（20261116）」は、分ける前の設計（H1 と M1 を合わせたもの）への所見。所見 4・7 と論点 D・E は M1 の設計に、それ以外はこの本文に反映した。

## 目的

- レビューの検証役（review-verify）がリポジトリ本体を書き換えても、必ず気づけるようにする。今は本文の注意書きだけで、実際に事故が起きた（`.steering/skill-issues.md` の 20261114）
- 事故の原因だった「写しや一時リポジトリを作る・移る」の失敗を、スクリプトの中で止める
- 評価（`claude plugin eval`）で、見張りが動いていること自体も確かめられるようにする（できない場合は、できないと記録して閉じる）

## 決定済み（20261116・ユーザー。すべて推奨案）

- 「検出して差し戻す」。検証役の Bash は残す
  - 却下: Bash を外す — 実装を壊してテストを流す再現ができなくなる
  - 却下: PreToolUse でコマンドを解析して止める — 事故の形（`cd` が失敗して後続がリポジトリの根で動く）は文字列から見抜けない
- 見張りの対象は review-verify だけ
  - 却下: Bash を持つ subagent すべて — 実装を任せた subagent の正当な書き込みを毎回差し戻す
- 検証役の間にユーザーが編集したときの誤検知は許す。差し戻しの文面で「覚えのない違いには触らない」と伝える
- 差し戻しは agent ごとに 1 回まで。2 回目からは記録だけにする
- 写しからは `.git` を除く
- 評価で hook が発火するかを、実装の最初に 1 回流して確かめる
- 評価の `scratch_ok` の正規表現は変えない。見張りの grader で補う。評価で見張れないと分かったら、`eval/README.md` に「この穴は評価では見えない」と書いて閉じる
- 課金のある回帰は、試し実行 1 回と、写しの作り方が変わる t2 と、本文を変えたスキルの停止のケース（l1）に絞る

## 対象 / 対象外

対象:

- 写しと一時ディレクトリを作るスクリプト
- 検証役の開始時と終了時に作業ツリーを比べる hook（マスター・雛形・評価の plugin）
- 見張りの知らせを受けたときの、スキルの側の手順
- 見張りを見る評価の grader

対象外:

- git が無視するファイルへの書き込み（`node_modules` の下のキャッシュなど）。git から見えないので、この hook では分からない。`review-verify.md` の「リンクにせず複製する」の注意書きは残す
- review-verify 以外の agent（ほかの 5 本は Bash を持たない）
- agent が使えないときの代替（汎用の subagent に同じ指示を渡す）。agent 名で絞るので、代替には hook が効かない。スクリプトは代替でも使う
- 事故を事前に防ぐこと。見張りは、起きた後に気づく仕組み

## 前提

公式で確かめたこと（2026-11-16 取得）:

- `SubagentStart`・`SubagentStop` は agent 名で絞れる。plugin の agent は `<plugin 名>:<agent 名>` になる（評価では `eval-c:review-verify`）
- `SubagentStart` は subagent の再開でも走る
- `SubagentStop` は差し戻せる。exit 2 の stderr が、subagent への次の指示になる。入力に `agent_id`・`agent_type`・`stop_hook_active` がある
- 親に伝えるには `PostToolUse` の `Agent` を使う（公式の案内）
- agent の frontmatter の `hooks` は plugin の subagent では無視される。だから hook は settings（評価では plugin の `hooks/hooks.json`）に置く
- `claude plugin eval` は plugin の hook を読み込み、hook は sandbox の外で動く。grader にコマンドを流す種類は無く、`regex` はワークスペースのファイルの中身と trace を見られる

このセッションで見たこと:

- Agent ツールの結果は、subagent の起動の直後に返った（終了の通知は別に届いた）。`PostToolUse(Agent)` が終了の後に来るとは限らない

確かめられていないこと（tasklist の 0 で確かめる）:

1. 評価の実行（`claude -p`）で、plugin の `SubagentStart`・`SubagentStop`・`PostToolUse(Agent)` が発火するか
2. `PostToolUse(Agent)` がいつ来るか（起動の直後か、終了の後か）。入力から agent の id を引けるか
3. hook の stderr や `additionalContext` が、評価の trace に載るか
4. 評価の sandbox で、スクリプトが `$TMPDIR` に書けるか
5. 差し戻しが続いたときに、Claude Code の側に上限があるか（公式の該当箇所を読む。無料）

`docs/knowledge/frontend-design.md` を読んだ。UI の設計の知見で、このタスクには関係しない。

## 振る舞い

### a. 写しと一時ディレクトリを作るスクリプト

`frontend-code-review/scripts/make-copy.sh`（新規）。

```
make-copy.sh            作業ツリーの写しを作り、絶対パスを 1 行で出す
make-copy.sh --empty    空のディレクトリを作り、絶対パスを 1 行で出す（一時リポジトリ用）
  GIT=<path>                 使う git
  MAKE_COPY_TIMEOUT=<秒>     複製の打ち切り（既定 60）
```

- 置き場所は `$TMPDIR` の下。名前に決まった接頭辞（`review-copy.`）を付ける
- 写しには `.git` を入れない（worktree では `.git` が本物の gitdir を指すファイルで、複製すると写しの中の git が本物の索引に書く）。`node_modules` はリンクにせず複製する
- 複製は、macOS は `cp -cR`、それ以外は `cp -a --reflink=auto` にする
- 失敗のときは 0 以外で終わり、パスを出さず、作りかけを消す: `TMPDIR` が無い・書けない／複製の失敗／打ち切り／作った先がリポジトリの根の下にある（`TMPDIR` がリポジトリの中を指す設定への備え）
- 後片付け: 呼ばれるたびに、同じ接頭辞で 1 日より古いものを消す。今回の写しは消さない（検証役が使い終わる時点をスクリプトは知らない）
- `review-verify.md` を次のように変える: 写しと一時ディレクトリはこのスクリプトだけで作る。その後の Bash のコマンドは、毎回 `cd <出たパス> && ...` で始める（`cd` が失敗したら後続が動かない形）。スクリプトが失敗したら再現をやめ、読みで判定し、その旨を根拠に書く
- スキルの Step 3 が、検証役への依頼文にスクリプトのパスと、要るなら `GIT=<パス>` を書く

### b. 作業ツリーの見張り

`.claude/hooks/subagent-tree-guard.sh`（新規。配る）。引数でモードを分ける。

**控える中身**（`git --no-optional-locks` で読む）:

- HEAD のコミット
- ref: ブランチ・タグ・stash（リモートの ref は見ない。IDE の自動 fetch で変わるため）
- 追跡ファイルの中身: `git diff HEAD` と `git diff --cached` のハッシュ
- 未追跡のファイル: 1 つずつの一覧（ディレクトリに畳まない）と、各ファイルの中身のハッシュ

`git status` の出力は使わない（既に変更のあるファイルをさらに書き換えても行が変わらないため）。

**モード:**

| モード | イベント | 動き |
|---|---|---|
| `start` | `SubagentStart`（matcher: `review-verify`） | リポジトリの根を入力の `cwd` から決め、上の中身を `${TMPDIR}/claude-tree-guard/<session_id>/<agent_id>/` に控える。**控えが既にあれば上書きしない**（再開で汚れた状態を控え直さない） |
| `stop` | `SubagentStop`（同じ matcher） | 控えと今を比べ、「確かめた」印と結果（同じ／違う）を記録する。違えば、違い（増えたコミット・変わった ref・変わった／増えた／消えたファイル）を stderr に出して exit 2 で差し戻す。差し戻しは agent ごとに 1 回だけ。2 回目からは 0 で通し、今も違えば「戻っていない」と記録する |
| `report` | 0 の結果で決める（下） | 未報告の記録のうち、違いのあったものを親に知らせる（今も違うか、戻ったか）。知らせた記録には報告済みの印を付ける |

**差し戻しの文面**（検証役へ）: 違いの一覧。自分が作った・変えたものだけを戻すこと。覚えのない違いには触らないこと。戻したことと、戻せなかったものを報告に書くこと。

**親への知らせの文面:** 違いの一覧と、今も違うかどうか。「検証役の間に変わった」とだけ書き、検証役のせいと断定しない。**自分では戻さず、ユーザーに示すこと。**

**`report` をどのイベントに置くか**（前提の 2 で決まる）:

- `PostToolUse(Agent)` が終了の後に来て、agent の id を引ける → そこで、その agent の記録を読む
- 起動の直後に来る、または id を引けない → `PostToolUse(Agent)` と親の `Stop` の両方で、その session の未報告の記録をすべて読む（`Stop` では、未報告の違いがあれば 1 回だけ差し戻して親に知らせる）

**場合分け:**

- 控えが無い（`start` が動かなかった・`agent_id` が取れない）: `stop` は比べず 0。素通しであることを stderr に 1 行出し、「確かめていない」と記録する
- git が無い・リポジトリの外・jq が無い: 素通し（ほかの hook と同じ）
- 検証役の間に、ユーザーや親が作業ツリーを変えた: 違いとして出る（誤検知）。上の文面のとおり、検証役も親も戻さない
- 検証役が同時に 2 体動く: 記録は `agent_id` ごと。片方の書き込みは、もう片方の違いにも出る（上と同じ扱い）
- worktree の中: 根は入力の `cwd` から決める（`stop-test-gate.sh` と同じ）
- 記録の掃除: `start` が、1 日より古い session の記録を消す

### c. 知らせを受けたときのスキルの手順

`frontend-code-review/SKILL.md` の Step 3 に足す: 見張りの知らせ（作業ツリーが変わった）があれば、**自分では戻さない**（`git restore`・`git checkout`・`git reset` を打たない）。Step 4 の報告の先頭に、違いの一覧と今も違うかどうかを警告として書く。レビューの指摘はそのまま続けて報告する。

### d. 評価

前提の 1 と 3 が成り立つ場合だけ行う。

- `prepare.sh` が、review の C のときに `eval/hooks/hooks.json` を**生成する**（今は追跡している静的なファイル。追跡をやめ、ほかのグループでは今と同じ中身を生成する）。見張りのスクリプトを plugin の `hooks/` に複製し、matcher を `^eval-c:review-verify$` にする
- review のケースに grader `stop-tree-checked` を足す: 「確かめた」印が 1 回以上あり、「違う」の印が 0 回で合格。印が 1 回も無ければ不合格（hook が発火しなくなったことに気づける）
- 印をどこに残すかは前提の 3 で決まる。trace に載るなら trace の `regex`。載らないなら、評価のときだけ（`EVAL_` で始まる環境変数で切り替え）ワークスペースの `.git/` の下に記録を写し、ファイルの `regex` で見る

前提の 1 が成り立たない場合: `eval/` には手を入れず、`eval/README.md` に「検証役の作業ツリーへの書き込みは、評価では見えない。`test:hooks` のフィクスチャで hook を確かめる」と書く。

## テスト方針

- hook とスクリプトは、既存の型（`tests/hooks/run_fixtures.py`・`tests/skills/run_*.py`）で、一時リポジトリを作って流す。足すだけで、既存のフィクスチャは変えない
- SKILL.md と agent の本文の変更は、評価のケースで確かめる
- 「親が自分では戻さない」（c）は、評価で事故を起こさせるケースを作れないので、機械では確かめない。本文と知らせの文面の両方に書くことで補う
- このリポジトリには vitest が無く、Stop のテストのゲートは動かない。`test-exemptions.md` は作らない

## 残る論点

無い。前提の 1〜3 の結果で形が変わる所（`report` を置くイベント・印を残す場所・評価をやるか）は、上に分岐として書いた。結果が出たら decisions.md に書き、分岐のどちらを採ったかを 1 行で残す。

## 悲観的に見ると

- 見張りは事故を防がない。コミットが 1 つ増えてから気づく。戻すのは検証役で、戻し損ねることもある（そのときは親に「戻っていない」と伝わり、ユーザーに示される）
- 前提の 1 が成り立たないと、「評価で確かめる」は達成できず、`test:hooks` のフィクスチャだけになる。その場合でも、普段のセッションでは hook が効く見込みだが、普段のセッションでの発火も実地では確かめていない（tasklist の最後に、実際のレビューで 1 回確かめる項目を置く）
- 未追跡のファイルの中身をすべてハッシュにするので、未追跡の大きなファイルが多いリポジトリでは、検証役の開始と終了が遅くなる。時間は測っていない
- 写しは作業ツリー全体の複製で、大きなリポジトリでは 60 秒の打ち切りに当たりうる。そのとき検証役は再現をやめ、読みで判定する（レビューの質が下がる）
- 「親が自分では戻さない」は本文頼みのまま

## プレモータム所見（20261116）

攻撃役（premortem-attacker）の所見 10 件を、design.md とコードで裏取りした。本文の設計は書き換えていない。

### 採った穴

1. **見張りが `git status --porcelain` の出力だけを比べるので、起こりやすい事故を見逃す** — 根拠: 「H1-b」の `start` の控えは「HEAD・全 ref のハッシュ・`git status --porcelain` の出力」。既に ` M` のファイルをさらに書き換えても行は変わらない。未追跡のファイルの中身を書き換えても `??` のまま。未追跡のディレクトリの下に足しても `?? dir/` に畳まれる。レビューの既定の対象は未コミットの変更（`frontend-code-review/SKILL.md:21`）で、検証役は実装の行を壊して確かめる（`review-verify.md:37`）ので、この形が一番起こりやすい。完了条件 1 の「追跡ファイルが変わったら 2」は、きれいな状態から変える場合しか表していない — 提案: 控えに中身を入れる（`git diff HEAD` と未追跡ファイルの中身のハッシュ。`stop-test-gate.sh:137-147` と同じ作り方）。完了条件 1 に「既に変更のあるファイルをさらに変えた」「未追跡のファイルの中身を変えた」「未追跡のディレクトリの下に足した」を足す
2. **親が「戻っていない」と知らされたときに何をするかが無い** — 根拠: 「H1-b」の `report` は親の context に知らせるだけで、構成の `SKILL.md` の変更（Step 1・3・4）に受けたときの手順が無い。親が `git restore` で戻すと、ユーザーが同時に編集した分を消す。`git restore *` は sandbox の除外にあり（`settings.json:73`）、ask にも無い — 提案: スキルに「見張りの知らせがあれば、自分では戻さない。違いの一覧を報告の先頭の警告として示して止まる」を書き、知らせの文面にも同じことを入れる
3. **`make-copy.sh` が 3 つの場面で働かない** — 根拠: 「H1-a」
   - worktree では `.git` がファイルで、本物の gitdir を絶対パスで指す。そのまま複製すると、写しの中の git が本物の索引と ref に書く。設計に写しの `.git` の扱いが無い
   - 評価の sandbox では素の git が rc=72 で落ちる（`eval/README.md:56`）。既存の 2 本は `GIT=` を受けるが（`count-diff.sh:47`・`run-tests-on-base.sh:54`）、`make-copy.sh` の仕様に無い
   - 実際の事故は、作業ツリーの写しではなく一時リポジトリの作成（`mktemp -d` → `cd` → `git init` → コミット。`.steering/skill-issues.md:11`）。「写しはこのスクリプトだけで作る」は、一時リポジトリを作るときの道を示していない
   — 提案: 写しの `.git` の扱いを決める（下の論点 A）。`GIT=` を受けて Step 3 で渡す。一時リポジトリ用のモードを足すか、`cd` の後に場所を確かめる手順を `review-verify.md` に書く。テストに「`.git` がファイルの worktree」を足す
4. **免除の拾い方が、ゲートが効かせる免除と一致しない。漏れた分は「なし」と報告される** — 根拠: 「M1-a」は行の形を `- <パス> — <理由>（YYYYMMDD）` とするが、ゲートは `"- "*" — "*` で理由が空でなければ効かせ、日付を求めない（`stop-test-gate.sh:86-91`）。日付の無い行は、ゲートは免除するのにレビューは「なし」と書く。目的の逆で、隠れた免除にお墨付きを与える — 提案: 行の判定をゲートの `exempt_paths` と同じ規則にする。完了条件 3 に「日付の無い行」を足す
5. **評価の `stop-tree-unchanged` は、見張りが動かなくても合格する** — 根拠: 完了条件 8 は「見張りが違いを知らせていなければ合格」。hook の登録の誤り・matcher の不一致・Claude Code の更新で発火しなくなっても合格する。論点 1 の確かめは 1 回だけ。加えて、`prepare.sh:58` が `hooks/` で消すのは `skill-claude-md.md` だけで、`eval/hooks/hooks.json` は追跡中の静的なファイル。書き換えると作業ツリーが汚れたまま残る。hook スクリプトを plugin へ複製することも構成に無い — 提案: 見張りは違いの有無にかかわらず毎回、確かめた印を残す。grader は「確かめた印が 1 回以上あり、違いの印が 0 回」で合格にする。`prepare.sh` は `hooks.json` を毎回生成する形にし、スクリプトの複製を構成に足す
6. **完了条件 9 と論点 2 の推奨 (b) が食い違う** — 根拠: 完了条件 9 は既存の 8 ケースすべてが同じ合否。推奨 (b) は n1・p2・r-c・t1 を流さない。推奨どおりだと、完了条件 9 は確かめられないまま完了になる — 提案: 完了条件 9 を、論点 2 で流すと決めたケースに合わせて書き直し、流さないケースと理由を decisions.md に残す
7. **pr-create の集め方に取りこぼしがあり、レビューの側と数が合わない** — 根拠: 「M1-b」はパスの書き方を決めていない。`.steering/*/test-exemptions.md` を引用符なしで書くと、シェルが今あるフォルダだけに展開し、閉じたタスクの分（この節が狙う場合そのもの）が消える。また「M1-a」は「理由だけ変わった: 載せない」だが、`git log -p` では書き換えが足された行に出る — 提案: コマンドのパスは引用符つきで、git の glob の書き方にする。論点 3 を見直し、同じ処理を `count-diff.sh` の別モードとして共有する案も比べる（機械でテストでき、依存も増えない）
8. **差し戻しの繰り返しに上限が無く、誤検知が起きやすい** — 根拠: 「H1-b」の場合分けは「違いが前回と同じなら通す」。違いが毎回変わると（エディタの自動保存・検証役が一部だけ戻した）差し戻し続ける。「全 ref」には `refs/remotes/*` が入り、IDE の自動 fetch だけでも差し戻す — 提案: agent ごとの差し戻しに上限を置き（下の論点 C）、超えたら記録だけにする。比べる ref を HEAD・ブランチ・タグ・stash に絞る。フィクスチャに「2 回目で違いが変わった」「リモートの ref だけ変わった」を足す
9. **agent をバックグラウンドで動かしたときと、再開したときの順序が無い** — 根拠: 「H1-b」の `report` は、`PostToolUse(Agent)` が subagent の終了の後に来る前提。このセッションで攻撃役を起動したとき、Agent の結果は起動の直後に返った（実測。終了の通知は別に届いた）。その時点では記録が無く、知らせは出ない。また公式は `SubagentStart` が再開でも走ると書いている（前提の調査で取得）。同じ `agent_id` で `start` が再び走ると、汚れた状態を新しい控えとして上書きする — 提案: `start` は既にある控えを上書きしない。`report` は記録がまだ無いときに何もせず、未報告の記録を拾う別の経路（次の Agent の後か、親の Stop）を足す。論点 1 の確かめに「バックグラウンドで起動したときに `PostToolUse(Agent)` がいつ来るか」を足す
10. **`make-copy.sh` の時間・後片付け・移植性と、`count-diff.sh` の新しい失敗の扱いが決まっていない** — 根拠:
    - 「H1-a」は作業ツリー全体を毎回複製するが、時間を測っておらず、打ち切りも無い（既存の `run-tests-on-base.sh:48` は打ち切りを持つ）
    - 写しをいつ誰が消すかが無い（`run-tests-on-base.sh:92` は `trap` で消す）。レビューのたびに `$TMPDIR` に溜まる
    - 「macOS は `cp -cR`」としか書いていない。GNU の cp の `-c` は意味が違う
    - `count-diff.sh` が 0 以外で終わるとレビュー全体が止まる（`frontend-code-review/SKILL.md:25`）。免除を読む処理の失敗まで致命的にするかが無い
    - 既存のテストの `parse`（`tests/skills/run_count_diff.py:68-87`）は、`dirstat:` の後の字下げされた行をすべて dirstat に入れる。`exemptions` を末尾に置くと既存の期待が崩れる
    — 提案: スクリプトに打ち切りを持たせる。写しを消す役と時点を決める。Linux の複製の仕方を分ける。免除を数えられないときは「分からない」と出して続け、報告に書く。出力の位置は `untracked` の前にし、tasklist の 0 で `parse` を直す

### 人が決める論点

- **A. 写しの `.git` をどうするか** — 選択肢: (a) 写しから `.git` を除く（写しの中で git は使えない。一番安全）／(b) 除いたうえで `git init` し直す（写しの中で diff を取れる。履歴は無い）／(c) そのまま複製し、worktree のときだけ失敗にする。推奨: (a)。検証役が写しの中で git を使う必要があるかは、過去の trace を読んでいないので分からない
- **B. タスクを分けるか** — 採った穴を入れると、H1 だけで hook・スクリプト・スキル・評価の 4 か所に手が入る。選択肢: (a) このまま 1 つで進める／(b) M1（免除の見える化）を先に別の PR で出し、H1 は論点 1 の確かめの後に進める。推奨: (b)。M1 は Claude Code の未確認の挙動に頼らず、無料の検査だけでほぼ確かめられる。H1 は論点 1 の結果で形が変わる
- **C. 差し戻しの上限** — 選択肢: (a) 1 回／(b) 2 回。推奨: (a)。戻せるものは 1 回で戻る。2 回目からは検証役が「覚えのない違い」に手を出す危険の方が大きい
- **D. 足して後で消した免除を PR に載せるか** — テストを書いて免除を消した場合。選択肢: (a) 載せない（PR の時点で残っているものだけ。ただし、タスクを閉じて消えた免除は載せる）／(b) 足した行をすべて載せる。推奨: (a)。(a) は「閉じたから消えた」と「解消したから消えた」を区別する処理が要る
- **E. `.steering/` を gitignore している配置先を対象にするか** — ゲートはその配置先を想定している（`stop-test-gate.sh:133` のコメント）。その場合、差分にも `git log` にも免除は出ない。選択肢: (a) 対象外と明記し、免除ファイルが無視されているときは「確かめられない」と出す／(b) ディスクの中身を読んで全行を載せる。推奨: (a)。このリポジトリと README は `.steering/` をコミットする運用
