# 決定の記録: skill-patterns-split

## 20260811 — 節の見出し文字列を一字も変えない

**決定**: 「停止・承認・前提条件の契約はハードストップの手順として書く（説明文では守られない）」の
見出しは変更しない。

**理由**: 手順 1 の全文検索で、設計が見込んだ 2 件（`skill-test/SKILL.md:52`・
`scripts/passthrough_check.py:5`）に加えて **2 件**が見つかった:
- `skill-design-patterns.md:552`（自ファイル内の相互参照。「課金を伴う操作は前置承認の
  ハードストップにし」節から「同じ規律」として参照）
- `.claude/hooks/remind-config-docs.sh:53`（要点注入文が見出し文を要約として引用）

4 箇所すべてが見出し**文**で参照しているため、見出しを変えると 4 件の死んだ参照が生まれる。

**影響**: design.md の主要コンポーネントの想定（節を名指しする参照 2 件）を実測で 4 件に更新した。
うち付け替えが必要なのは 2 件のみ（残り 2 件は見出し不変で成立する）。

## 20260811 — 全文 Write ではなく Edit の分割で書き換えた

**決定**: 562 行のファイルを Write で丸ごと置き換えず、Edit を 4 回に分けて適用した。

**理由**: Write は変更しない 380 行を再入力することになり、転記ミスが差分に紛れても
機械検査（`validate_skills.py` はこのファイルの内容を見ない）では検出できない。
Edit なら不一致で失敗するため、変更範囲を外れた改変が構造的に起きない。

**影響**: 手順が増えるが、リグレッション懸念（design.md の影響範囲に記載した
「機械では検出できない」欠陥）の実際の露出面が縮んだ。

---

## 20260811 — 新ファイルのポインタ位置は Step 3 冒頭にした（設計どおり・但し書きあり）

**決定**: `skill-test/SKILL.md` の Step 3 冒頭に置いた。

**理由**: design.md の主要コンポーネントの指示どおり。ただし設計の根拠文には
「シナリオを書く前・コスト提示前に要る情報のため」とあり、Step 3 はコストゲート（Step 2）の
**後**なので、根拠文と配置指示にわずかな不整合がある。

配置指示（Step 3 冒頭）を優先した。理由は、新ファイルの内容の主軸が「結果の読み方」と
「測定ログ」で、どちらも実行層に入ってから要るものだから。シナリオ執筆はこのスキルの
ステップではない（シナリオは `tests/passthrough/` の資産）。

**影響**: 乖離としてはエスカレートしない（設計の明示指示に従っているため）。
将来シナリオ執筆のステップを設けるなら、そのときポインタを前倒しする。

## 20260811 — 規律の突合はフレッシュなサブエージェントに回した

**決定**: 圧縮前に規律 21 件 + 手順 5 件を機械抽出して固定し（`rules-fixed.md`）、
圧縮後にフレッシュなサブエージェントへ「落ちた規律を挙げよ」と突合させた。

**結果**: 欠落 0 / 重複 0。軽微な差分 3 件の指摘のうち 1 件
（R4 の「または empirical-prompt-tuning」の消失）を復元した。

**理由**: 圧縮した本人が検証すると、同ファイル自身が実測している「自己レビューは自分が書いた
中核ロジックを構造的に見落とす」に該当する。design.md の完了条件に組み込んでいた。

**影響**: この突合手順（抽出 → 固定 → 別エージェントで差集合）は、機械検査が内容を見ない
ドキュメント改訂の一般的な検証パターンとして再利用できる。
