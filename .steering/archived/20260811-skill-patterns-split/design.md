## 目的

`docs/knowledge/skill-design-patterns.md` は 562 行あり、CLAUDE.md がスキル作成・改善時の必読に
指定しているため**このリポジトリのほぼ全タスクで読まれる**。うち 175 行（31%）が
「停止・承認・前提条件の契約」1 節に集中し、その中身は (1) スキル執筆の規律と
(2) 素通り検査の運用手順という**消費者の異なる 2 種類**が混在している。加えて同じ規律が
20260703 から 20260725 まで時系列で 7 回言い直されており、読み手は 7 周してから規律に到達する。
運用手順を唯一の消費者（`skill-test`）の隣へ移し、時系列の重複を規律の正本に畳んで、
スキルを書くたびに払う読み取りコストを下げる。`.steering/BACKLOG.md` 節 1(c) の宿題。

## アプローチ

節を「規律の正本（箇条書き）→ 代表実例 2 件 → 結論 → 新ファイルへのポインタ 1 行」の順に再構成する。
時系列に追記された 7 実例は、同じ規律を段階的に強化した記録なので、**規律を先に確定してから
実例を選ぶ**（実例を削る作業ではなく、規律を抽出して実例を後から当てる作業として進める）。
移動するのは**純粋なテスト運用手順のみ**（現 239-251 / 331-346 / 362-371 の表）で、
執筆規律が混ざる 311-317・325-330 と、結論である 372-381 は正本に残す。
新ファイルは `skill-test/SKILL.md` に既にある記述（SHA1 判定・自己申告不使用・4 run 規律）を
**複製しない** — 同じ規律が 3 箇所に並ぶのは本タスクが解消しようとしている構造そのもの。

## テスト方針

Markdown 中心の変更のためユニットテストは無い。検証は次の 4 層:

1. **機械検査**: `validate_skills.py` + `check_asset_consistency.py` を全 PASS で維持
   （件数は着手時ベースラインと比較。HEAD と作業ツリーで契約数が違うため絶対値で書かない）
2. **行数の実測**: 節 85 行以下・全体 472 行以下を `wc -l` と見出し行番号の差で確認
3. **規律の保全（機械）**: 圧縮前に 209-383 の規律文を抽出して一時ファイルに固定し、
   抽出元の行番号との対応表を残す
4. **規律の保全（人以外の目）**: 圧縮後、**フレッシュなサブエージェント**に
   「固定した規律リストと圧縮後の本文を突合し、落ちた規律を挙げよ」と実行させる。
   実装者本人の自己判定にしない（同ファイル 385-395 行が自己レビューの盲点を実測している）

素通り検査（課金）は**回さない** — 本タスクは knowledge ファイルの再配置でスキル本文の停止契約を
変更しないため、実行層を回す理由がない。層 4 のサブエージェントは静的な突合のみで無料。
