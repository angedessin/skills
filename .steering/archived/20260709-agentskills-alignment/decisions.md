# Decisions — agentskills-alignment

Status: **保留（検討中）** — 20260709 の議論で「導入は一旦検討」に。design.md は DRAFT のまま未反映。

## 議論の結論（20260709）

### この差分導入では「ワークフローの完全さ」は上がらない
- 完全さは2軸に分かれる: 軸A=ライフサイクル/挙動のカバレッジ（＝ワークフローの完全さの本体）、軸B=スキル記述の衛生・仕様準拠。
- agentskills.io の内容はほぼ全部が軸B。採用3点も全部軸B で、軸A には触れない。
- 軸A の穴は `20260706-workflow-gap-analysis/proposal.md` が既に特定済み（S2 refactor / S3 dependency-update / A1 reviewer agent が残タスク）。完全さを上げたいならそちら。

### 採用3点の精査 → 導入すべきは実質ゼロ
| 項目 | 判定 | 理由 |
|---|---|---|
| 採用1 Gotchas 置き場 | **導入しない（有害）** | "Gotchas" 節＝末尾注記。skill-design-patterns.md 冒頭の「エッジケースは末尾に分離せず該当ステップに直接書く（孤立 subagent が末尾を読まない）」と正面矛盾 |
| 採用2 references 読み込み条件明記 | **導入しない（冗長）** | 既存2規律の言い換え: ①自己完結節「参照の代替動作を該当ステップに書く」②@参照のコスト注意（条件付き読込）。新規成果物不要 |
| 採用3 validator 仕様準拠チェック | **任意・弱** | 私が推した `allowed-tools` warn は「起きない事象への保険」で弱い。実利があるのは frontmatter typo/未知キー warn だが agentskills 由来の新規性は薄い。最も価値ある validator 追加（本文ツール API 出現ゼロの機械計測）はこのリポジトリ自身の基準で agentskills 差分ではない＝別枠 |

### 正味の残り（もしタスクを起こすなら）
- 採用が消えるので、残るのは「見送り判断を蒸し返さないための記録」だけ。
- 見送り確定: eval ループ2種（課金・ROI 不成立）・`allowed-tools` frontmatter（Experimental・クロスクライアント可搬性を毀損）・npx/uvx ランナー（pnpm ポリシーと衝突）。
- 警戒（記録価値あり）: 「理由説明 > rigid directives」という外部推奨は、停止・承認ゲートには適用しない（20260703-04 の配置検証で説明文の承認契約は3例とも破られ、ハードストップ手順だけが守られた実測と矛盾するため）。
