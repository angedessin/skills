# prompt-audit レポート: Claude Code 設定（skills リポジトリ）

## 前提

- **対象範囲:** プロジェクトの `CLAUDE.md`、`.claude/skills/*/SKILL.md`（30 本）、`.claude/agents/*.md`（12 本）、`~/.claude/CLAUDE.md`（セッションに注入された本文 1 行）。プロジェクト内にほかの `CLAUDE.md` / `CLAUDE.local.md` / `AGENTS.md`、`rules/`、`commands/`、`output-styles/`、import は見つかりませんでした。
- **読めなかったもの（権限で拒否）:** 祖先ディレクトリの `CLAUDE.md` の有無、`~/.claude/` 配下の skills / rules / agents / commands、managed-policy の `CLAUDE.md`、プラグイン（figma、feature-dev、code-simplifier、skill-creator、anthropic-skills）のスキル。スキル一覧に出ている `find-skills` / `modern-web-guidance` / `gemini-search` はユーザー階層かプラグインのものと思われますが、本文は未確認です。`gemini-search` は名前から他社プロバイダ（Gemini）を使うものと推測しますが、未読のため確認していません。
- **対象モデル:** 本文と CLAUDE.md は、このセッションのモデル（Claude Opus 5.5）。サブエージェントは frontmatter で固定されたエイリアスで見ています（haiku→Haiku 4.5、sonnet→Sonnet 5.5、opus→Opus 5.5）。
- **リクエストを組み立てるコードは対象範囲にありません。** そのため Group 4 は、サブエージェント構成のチェックだけを行いました。

## サマリー

いちばん影響が大きいのは `empirical-prompt-tuning` に集中した 3 件です。

- **CLAUDE.md との矛盾:** Iteration 0 に「ユーザー確認なしで Claude が直接修正する」とあります。一方 `CLAUDE.md:40` は「SKILL.md への書き込みは承認制」です。git blame では CLAUDE.md 側が新しく、より厳しいルールです。
- **同じファイル内の矛盾:** 「1 修正 1 イテレーション」（205 行目）と「1 イテレーション 1 テーマ、関連修正はまとめて良い」（67・195 行目）が食い違っています。
- **古いツール名:** 141 行目の「Task tool」は、同じファイルの 60 行目では「Agent tool」になっています。

ほかに、改訂の経緯を語る文（「以前は…整理した」）が 2 件あります。

全体としては、強調表現・思考を誘導する定型文・古いモデル向けの回避策はほとんどありません。大量にある「承認の代用にしない」「ここで止まる」系の文は、承認ゲートやハードストップという壊れやすい操作の契約です。実際に起きた失敗が理由として添えられているので、keep list に当たり残すべきものです。

**件数:** Group 1: 2 件（どちらも Low・flag） / Group 2: 7 件（High 1・Medium 4・Low 2） / Group 3: 対象なし（ツール定義なし） / Group 4: 1 件（Low・flag）
