## 福利化ドラフト

### 1. リストの `key` に配列の index を使わない
**書き込み先:** CLAUDE.md にルールを1行追加

**理由:** 3回のレビューすべてで Medium として指摘されています。どれも同じ原因で、行の削除・追加・並び替えのたびに入力や開閉の状態が別の行にずれました。
- cart `CartList.tsx:14`：削除すると数量の入力欄の値が隣の行にずれる
- orders `OrderHistory.tsx:22`：新しい注文が先頭に入ると、開いた行の状態が別の注文に移る
- favorites `FavoriteList.tsx:11`：並び替えるとチェックがずれる

**状態:** 実証済み（3回とも同じ直し方で解決）

**追加する内容:**
```
## スタック制約（行動ルール）
- リストの `key` に配列の index を使わない。`id` など、データ側で一意に決まる値を使う（行の追加・削除・並び替えで、入力や開閉の状態が別の行にずれる）
```

**今のコードに残っている違反:** 1件見つかりました。採用されたら同じ作業の中で直します。
- `src/features/products/RecentKeywords.tsx:7` が `key={i}` になっています。行ごとに削除ボタンがあるので、まさに同じ問題が起きる形です。
  - 直し方：`key={k}` にして、`onRemove` は index ではなくキーワードの文字列を受け取るように変えます。
  - ただしこれは、キーワードに重複がないことが前提です。今は呼び出し元がないので、重複をなくすのは入力側の責任として、その前提をコメントに書いておきます。

**参考（今回は提案しません）:** ESLint の `react/no-array-index-key` を使えば機械的に止められます。ただ、このプロジェクトには ESLint 自体が入っていないので、先に入れる必要があります。CLAUDE.md のルールを足しても再発するようなら、そのとき改めて提案します。
