# knowledge-capture

次の作業で読み返したときに役立つものだけを残す。書き込みの案を示したら止まり、承認をもらってから書く。

## When NOT to use

- README・仕様書・コードのコメントの編集 → このスキルを使わず、普通に編集する
- 繰り返す摩擦をルールや仕組みに昇格させる → このスキルの対象外（頼まれたら、繰り返す事象を探して昇格の案を出す）

## Step 1 — 材料を読む

- 対象のタスクのフォルダ（`.steering/[task]/` の design.md・tasklist.md・decisions.md・review-result.md・blockers.md など、あるものすべて）と、この会話で分かったこと
- 既に残っているもの: `docs/knowledge/` の各ファイル・CLAUDE.md。同じことが既に書いてあれば、新しく足さない
- 材料が指すコードが実際にあるかも確かめる。食い違いがあれば、案と一緒に伝える
- `.steering/` が無いときは、この会話の内容だけを材料にする

## Step 2 — 残すものを選ぶ

| 知見 | 扱い |
|---|---|
| 別の作業でも起こりうるハマりどころ・パターン（原因と避け方が言える） | `docs/knowledge/[topic].md`。既存のファイルと節に寄せる。合うものが無ければ新しいファイルを案にする |
| そのタスクの設計の決定（なぜそうしたか・却下した案） | タスクの decisions.md。既に書いてあれば何もしない。一般の知識に書き換えない |
| 毎回守らせたい 1 行の命令 | CLAUDE.md。既にある規則と重なるなら足さない。長い説明は docs/knowledge/ に置く |
| 直して終わった一回限りのこと（typo・命名・その場の修正） | 残さない |

迷ったら残さない側に倒す。残す数が多いほど、読み返されなくなる。

## Step 3 — 書き込み案を示して止まる

案ごとに書くこと:

- 何を残すか（1〜3 行で。原因と避け方が分かる形）
- 保存先（ファイルと節。新しいファイルならその旨）
- 材料のどこから来たか（ファイル名）

続けて、残さないと決めたものを理由つきで 1 行ずつ挙げる（既にある・一回限り・タスクの決定として残っている）。

**ここで止まる。** CLAUDE.md・`docs/` には、承認をもらう前に書かない。「全部」「1 と 3」のように採るものを返してもらい、採ったものだけを Edit / Write で書く。
