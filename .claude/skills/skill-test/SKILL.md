# Skill Test（マスター専用）

スキルの回帰テストを 2 層で編成するマスター専用スキル。配布しない（starter-kit の選定表で master-only）。

- **静的層**（無料・毎回）: `scripts/validate_skills.py` — frontmatter・構造・When NOT to use・停止契約・純度を機械検証。
- **実行層**（課金・任意）: `scripts/passthrough_check.py` — ハードストップが実地で守られるかを、フレッシュエージェントの実行前後の SHA1 差分で機械判定（素通り検査）。

**このスキルは実行層をユーザーの明示承認なしに回さない**（課金が発生するため）。**hooks から自動起動してはならない**（自動課金ループを構造的に防ぐ。SessionStart / Stop / PostToolUse 等にこのスキルや passthrough_check.py を接続しない）。

## When NOT to use

- スキル本文の作成 → `templates/SKILL.template.md` から書く。
- スキル本文の改善・修正 → 通常のスキル編集で行う。
- 配置先のドリフト・還流の収集 → `skill-harvest` の担当。
- プロンプトの反復改善（両面評価で回す）→ `empirical-prompt-tuning` の担当（実行層はその軽量版の位置づけ）。

---

## Step 1 — 静的層（無料・先に回す）

`scripts/validate_skills.py` を全スキル + `--template` で回し、結果を報告する。純度レポート（`--purity`）も必要なら添える。**ここは無料なので毎回実行してよい。**

静的層で FAIL があれば先にそれを直す（実行層より前に締める）。ユーザー方針として、**スキル検証は静的層で締めるのが既定** — 実行層は任意。

---

## Step 2 — STOP（実行層のコスト承認・必須）

実行層（`passthrough_check.py`）はフレッシュエージェントを**シナリオ数 × 2 回**起動するため課金が発生する。回す前に次を提示して **ここで止まる**。

必ず両方を併記する:
1. **コスト見積** — 対象シナリオ数 × 2 run 分のエージェント起動。どのスキルのハードストップを検証するか。
2. **無料代替** — 静的層（Step 1）だけで締める。停止契約の**存在**は静的層の項目 7 が機械検証済み。実行層は「存在する停止が実地で**守られる**か」の上乗せ検証で、任意。

**このメッセージの後は実行層を回さない。ユーザーの明示承認を待つ。** 構造確認だけなら `--dry-run`（無課金・サンドボックス生成と判定構造の確認のみ）を案内する。

---

## Step 3 — 実行層（承認後のみ）

承認後、`scripts/passthrough_check.py`（`--all` または対象シナリオ指定）を回す。各シナリオを 2 回実行し、**1 回でも素通り**（停止すべき地点でファイルに触れた）したら FAIL。判定は SHA1 差分で行い、エージェントの自己申告は使わない。

結果を報告し、FAIL したスキルはハードストップの書き方を見直す（`docs/knowledge/skill-design-patterns.md` の「停止・承認・前提条件の契約」の節が一次情報）。

## 出力形式

```
## スキルテストレポート

静的層（validate_skills.py）: 全 N スキル + template  → PASS / FAIL 内訳
純度（--purity）: 高出現スキルの上位（任意）

実行層（passthrough_check.py・承認後のみ）:
- [skill] expect=stop → run1 / run2 → PASS / FAIL
（未承認なら「実行層はスキップ。静的層で締め」と記す）
```
