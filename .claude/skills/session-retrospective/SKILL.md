# session-retrospective

あとで改善の材料になるよう、摩擦だけを記録する。直すのはこのスキルの役割ではない。

<!-- validator: no-stop-needed — .steering/ への記録は承認の要らない範囲で、CLAUDE.md・docs/・.claude/ には書かない -->

## When NOT to use

- 作業で得た知見（パターン・ハマりどころ）の保存 → このスキルを使わない。保存先の案を示して承認をもらってから書く
- 摩擦をルール・hook・スキルの修正に昇格させる → このスキルの対象外。頼まれたときに、記録を材料にして別に行う

## Step 1 — 摩擦を拾う

この会話（貼られた記録があればそれ）を頭から読み、次に当たるものを拾う:

- ユーザーが方向を直した・やり直させた
- やり方が失敗して、別のやり方に切り替えた
- ユーザーがツールの実行を拒否した
- 指示やスキルの本文が複数に読めて、迷った（迷ったまま決めて進めたなら、それも書く）
- スキルが発動すべきでないのに発動した・発動すべきなのにしなかった

普通に進んだ作業（足した・通った・終わった）は拾わない。摩擦が無ければ「記録する摩擦は無い」と 1 行で伝えて終わる。

既にある規則（CLAUDE.md など）を守らなかったための摩擦なら、その規則を挙げる。規則が足りないのか、守られなかったのかで、後の直し方が変わる。

## Step 2 — 記録する

記録先は、進行中のタスクのフォルダの `.steering/[task]/skill-issues.md`（無ければ作る）。どのタスクか分からないとき、`.steering/` が無いときは、返答に書くだけにする。

1 件ごとに:

```
## [YYYYMMDD] — [何が起きたか（1 行）]
**事象**: [起きたこと。分類（訂正・手戻り・拒否・曖昧さ・誤発動）]
**期待**: [どうすべきだったか]
**該当**: [関係する規則・スキル。無ければ「未特定」]
```

CLAUDE.md・`docs/`・`.claude/` には書かない（ルールへの昇格はしない）。

## Step 3 — 報告する

記録した件数・場所と、各件の 1 行の要約を返す。ユーザーに確かめたいこと（迷ったまま決めた解釈など）があれば、最後に聞く。
