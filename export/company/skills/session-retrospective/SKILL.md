# Session Retrospective

セッション終盤に、そのセッションで起きた摩擦を会話履歴から採掘し、`skill-issues.md` に起票するメタスキル。自己改善ループ（compound）の原料を「気づいたら書く」から「終盤にまとめて採掘する」に強化する。単独利用のメタスキル。

**このスキルは昇格（ルール化・スキル改修）をしない。** 起票までが役割で、ルールへの昇格は `compound` が別途行う。

## When NOT to use

- コード・設計・意思決定の知見保存（`docs/knowledge/`・CLAUDE.md への保存）→ `knowledge-capture` の担当。
- 摩擦をルール・lint・hook・スキルへ**昇格**させる → `compound` の担当（このスキルはその原料を作る）。
- CLAUDE.md 自体の肥大化・陳腐化の監査 → `rule-audit` の担当。
- タスク完了のたびに自動起動しない（明示依頼かセッション終盤の合図で起動する）。

---

## Step 1 — 採掘

現在の会話履歴を先頭から走査し、次の 5 分類で摩擦を抽出する:

- **(a) スキルの誤発動・不発動** — 発動すべきでないスキルが発動した、または発動すべき場面で発動しなかった。
- **(b) ユーザー訂正** — ユーザーが方向修正・やり直し・「そうじゃない」を指示した箇所。
- **(c) 手戻り** — あるアプローチが失敗して別アプローチに切り替えた箇所。
- **(d) パーミッション拒否** — ユーザーが tool 実行を拒否した箇所と、その含意（何をすべきでなかったか）。
- **(e) 指示・スキル本文の曖昧さ** — 解釈に迷った・複数解釈が可能だった箇所。

**5 分類すべてで該当ゼロの場合** → 「今回のセッションで起票すべき摩擦はありませんでした」と 1 行で報告して終了する。無理に起票しない（ノイズ起票の禁止）。

---

## Step 2 — 起票

各摩擦を次の形式で `skill-issues.md` に追記する:

```
## [YYYYMMDD] — [事象の要約]
**事象**: [何が起きたか（分類 a〜e のどれか）]
**期待**: [どうあるべきだったか]
**該当**: [スキル名 or ルール名。特定できなければ「未特定」]
```

**書き込み先の決定**:
- **アクティブタスクがある**（`.steering/[task]/` が存在する）→ その `skill-issues.md` に追記する。この追記は**承認不要**（このリポジトリの CLAUDE.md の自律実行境界に該当: git で巻き戻せる・失敗に気づける・影響がタスク内に閉じる）。
  - **CLAUDE.md にこの自律実行境界が明文化されていない場合** → 追記前に一言確認してから書く。
- **アクティブタスクが無い**場合 → `.steering/[YYYYMMDD]-retrospective/skill-issues.md` の作成を**提案して、ここで止まる**。ユーザーの承認を待ってから作成・起票する。これは `compound` の回収経路を 1 本（`.steering/**/skill-issues.md`）に保つため。**断られたら**抽出結果を会話に提示するだけで、ファイルは作らない。

---

## Step 3 — 報告

起票件数と分類別内訳を報告し、「これらの摩擦は次回の `compound`（福利化）実行時に回収され、ルール・スキルへの昇格が検討される」と案内する。**このスキルは昇格しない。**

## 出力形式

```
## セッション振り返り

起票: N 件（.steering/[task]/skill-issues.md）
- (a) スキル誤発動/不発動: X 件
- (b) ユーザー訂正: X 件
- (c) 手戻り: X 件
- (d) パーミッション拒否: X 件
- (e) 曖昧さ: X 件

次: compound での回収（昇格）は次回の福利化時に行われる。
```
